## 1. Conceptos

- **Medio**: un sitio de noticias (El País, la diaria, Montevideo Portal…).
- **Fuente**: una nota concreta de un medio (URL normalizada).
- **Snapshot**: captura del contenido de una Fuente en un momento dado.
- **Cambio**: diferencia entre dos snapshots de la misma Fuente.
- **Historia**: un mismo hecho cubierto por una o más Fuentes.
- **Hecho**: afirmación fáctica breve sobre una Historia, en nuestras palabras,
  respaldada por una o más Fuentes. *No se vota.* Es el archivo.
- **Proposición**: frase opinable derivada de una Historia
  ("La rebaja del IRPF es una buena medida"). *Se vota.* Es el juego y el
  insumo del clustering.
- **Entidad**: persona, organización o lugar (modelo existente de `core`).

> Separar Hecho de Proposición es clave: los hechos no se "acuerdan", se
> verifican. Las proposiciones sí se opinan. Polis funciona con lo segundo.

## 2. Arquitectura

```
                 ┌──────────── Celery beat ────────────┐
                 ▼                                     ▼
 RSS/sitemaps → descubrir → filtrar (barato) → extraer (pago) → snapshot (R2)
                                                   │
                                                   ▼
                              embeddings → agrupar en Historia
                                                   │
                                                   ▼
                     LLM: Hechos + Proposiciones + Entidades (+ verificación)
                                                   │
                ┌──────────────────────────────────┼──────────────────┐
                ▼                                  ▼                  ▼
        Archivo público                  Juego diario (5)     Re-crawl → Cambios
     (historias, entidades,           votos + predicción             │
      hechos, cambios, SEO)                    │                     ▼
                                               ▼              página "qué cambió"
                                   Clustering (core/clustering)
                                   mapa, consenso, puentes, reporte
```

**Apps**

| App | Responsabilidad |
|---|---|
| `archivo` | Medio, Fuente, Snapshot, Cambio, Historia, Hecho, Proposición; crawl, extracción, agrupamiento, LLM, páginas públicas del archivo. |
| `juego` | Selección diaria, voto, predicción, puntaje, racha, tarjeta compartible. |
| `core` | Usuarios, perfiles, sesiones, Entidad, clustering, reporte, emails. Lo viejo (Noticia/Voto) queda solo-lectura hasta borrarlo. |

**Interfaces intercambiables** (para no casarse con proveedores):

- `archivo/providers/extract.py`: `Extractor.extract(url) -> ExtractResult`
  con implementaciones `ContextDevExtractor`, `FirecrawlExtractor`,
  `TrafilaturaExtractor` (fallback/tests).
- `archivo/providers/decide.py`: `Decider.ask(pregunta, registro, tipo) -> valor`
  para decisiones tipadas (sí/no, opción, score). Implementación inicial con un
  LLM barato en modo JSON; se puede cambiar por Jev u otro modelo de decisión.
- `archivo/providers/embed.py`: embeddings vía LiteLLM.
- `archivo/storage.py`: `put_snapshot(bytes) -> key`, `get_snapshot(key)`
  (S3-compatible con `boto3`).

## 3. Modelos

### `archivo`

```python
class Medio(Model):
    nombre, slug, dominio (unique)
    rss_urls: JSON[list[str]]
    sitemap_urls: JSON[list[str]]
    secciones_incluidas: JSON[list[str]]   # patrones de URL: /politica/, /economia/…
    secciones_excluidas: JSON[list[str]]   # /deportes/, /espectaculos/, /horoscopo/…
    activo: bool
    pago: bool                              # tiene paywall (informativo)
    ultimo_descubrimiento: datetime

class Fuente(Model):
    medio: FK Medio
    url: URL (unique, normalizada con core.utils.normalize_url)
    url_hash: char(64) (index)
    titulo, bajada, autor
    publicada_en: datetime (index)
    descubierta_en: datetime
    estado: enum[descubierta, descartada, extraida, procesada, error, despublicada]
    motivo_descarte: char
    texto: text                             # texto extraído (no se publica completo)
    embedding: JSON[list[float]]
    historia: FK Historia (null)
    ultimo_snapshot: FK Snapshot (null)
    proximo_recrawl: datetime (null, index)

class Snapshot(Model):
    fuente: FK Fuente
    capturado_en: datetime
    storage_key: char                       # en R2
    contenido_hash: char(64)                # sha256 del texto normalizado
    titulo, texto_hash
    http_status: int
    proveedor: char

class Cambio(Model):
    fuente: FK Fuente
    antes: FK Snapshot, despues: FK Snapshot
    tipo: enum[titulo, cuerpo, despublicada]
    diff: JSON                               # ops de difflib, solo sobre texto
    cambia_sentido: bool (null)              # decisión tipada
    resumen: char                            # 1 frase: qué cambió
    relevancia: float                        # 0–1
    detectado_en: datetime

class Historia(Model):
    titulo, slug (unique), resumen
    categoria: enum[politica, economia, seguridad, salud, educacion, sociedad, internacional, otros]
    primera_fuente_en, ultima_fuente_en: datetime
    n_medios: int                            # cobertura
    centroide: JSON[list[float]]
    estado: enum[abierta, cerrada]           # cerrada tras 72 h sin fuentes nuevas
    procesada_en: datetime (null)

class Hecho(Model):
    historia: FK Historia
    texto: char(280)
    fuentes: M2M Fuente (through HechoFuente: cita_breve char(300), fiel: bool)
    entidades: M2M core.Entidad
    orden: int
    disputado: bool                          # fuentes se contradicen

class Proposicion(Model):
    historia: FK Historia
    texto: char(200)
    hechos: M2M Hecho                        # en qué se apoya
    entidades: M2M core.Entidad
    tema: char                               # etiqueta corta y estable ("IRPF", "seguridad")
    divisividad_estimada: float              # 0–1, decisión tipada
    calidad: float                           # 0–1, decisión tipada
    estado: enum[candidata, publicada, descartada]
    creada_en: datetime
```

### `juego`

```python
class Jornada(Model):

    proposiciones: M2M Proposicion (through JornadaItem: orden)

    prediccion: smallint (null)              # 0–4: bucket de % de acuerdo

class Racha(Model):                          # o campos en UserProfile

```

## 4. Pipeline de ingesta

Todos los tasks con `@task_lock`. Horarios en America/Montevideo.

| Task | Cuándo | Qué hace |
|---|---|---|
| `descubrir_medio(medio_id)` | cada 30 min por medio | Lee RSS/sitemap (`feedparser` / XML). Normaliza URL. Crea `Fuente(estado=descubierta)` si no existe. |
| `filtrar_fuente(fuente_id)` | al descubrir | Gratis primero: patrones de sección, idioma, antigüedad > 48 h → descarta. Luego decisión tipada sobre título+bajada: "¿noticia de interés público uruguayo (política, economía, sociedad)?" → sí/no. Cupo diario configurable (`MAX_EXTRACCIONES_DIA`, default 150). |
| `extraer_fuente(fuente_id)` | cola, rate-limited | Llama al Extractor pago. Guarda snapshot en R2, `texto`, metadatos. Programa `proximo_recrawl`. |
| `agrupar_fuente(fuente_id)` | tras extraer | Embedding de título+primer párrafo. Compara contra centroides de Historias abiertas (últimas 72 h). Si coseno ≥ umbral (≈0.82, calibrar) → asigna; si hay duda (0.72–0.82) → decisión tipada "¿mismo hecho?" sobre el par; si no → Historia nueva. |
| `procesar_historia(historia_id)` | cuando una Historia lleva 2 h sin fuentes nuevas, o tiene ≥ 3 medios, y de nuevo si entran fuentes nuevas | LLM: título, resumen, Hechos con procedencia, Proposiciones, Entidades. Ver §5. |
| `verificar_historia(historia_id)` | tras procesar | Por cada (Hecho, Fuente): decisión tipada "¿la fuente respalda esto?" → `fiel`. Hechos sin ninguna fuente fiel se borran. Proposiciones: score de calidad y divisividad. |
| `recrawl_fuente(fuente_id)` | según `proximo_recrawl` | Solo para fuentes de Historias "top" (§6). Re-extrae; si cambia el hash → `Cambio`. |
| `analizar_cambio(cambio_id)` | tras detectar | Diff con `difflib`. Decisión tipada "¿cambia el sentido?" + resumen de 1 frase. |
| `cerrar_historias` | cada hora | Marca cerradas las Historias sin actividad en 72 h. |
| `armar_jornada(fecha)` | 05:30 diario | §7. |
| `update_voter_clusters` | 02:00 diario (existente) | Ahora sobre `VotoProposicion`. |

**Política de recrawl** (presupuesto): solo Historias top del día (≈ 20) →
sus fuentes se re-capturan a las 24 h y a los 7 días. ≈ 40 fuentes × 2 = 80
re-extracciones/día. Detección de "despublicada" con un `HEAD` gratis antes de
pagar extracción: 404/410 o redirect a home → `Cambio(tipo=despublicada)`.

**Robustez**
- Reintentos exponenciales; errores del proveedor no consumen cupo.
- Si un medio da 0 fuentes nuevas en 24 h → alerta en el resumen diario de staff.
- Idempotencia por `url_hash` y `contenido_hash`.

## 5. LLM: esquemas y prompts

Se reutiliza el patrón de `core/parse.py` (LiteLLM + Pydantic + fallback de
modelos). Modelo principal: el flash-lite más barato que aguante JSON.

```python
class HechoOut(BaseModel):
    texto: str                     # ≤ 280, en nuestras palabras, sin adjetivos valorativos
    fuentes: list[int]             # índices de las fuentes de entrada que lo respaldan
    citas: list[str]               # cita breve literal por fuente (≤ 300 chars)
    entidades: list[str]

class ProposicionOut(BaseModel):
    texto: str                     # ≤ 200, opinable, afirmativa, sin negaciones dobles
    hechos: list[int]
    tema: str
    entidades: list[str]

class HistoriaOut(BaseModel):
    titulo: str
    resumen: str                   # ≤ 400
    categoria: Literal[...]
    hechos: list[HechoOut]         # 2–6
    proposiciones: list[ProposicionOut]  # 1–3
    entidades: list[EntidadNombrada]     # reutiliza el esquema existente
```

**Reglas del prompt de Historia**
- Entrada: hasta 6 fuentes (de medios distintos), cada una recortada a ~1.500 tokens.
- Hechos: solo lo que dicen las fuentes; indicar qué fuente(s); marcar si se contradicen.
- Proposiciones: que una persona razonable de cualquier lado pueda estar de
  acuerdo o en desacuerdo; nunca un hecho verificable; nunca sobre una persona
  privada; sin lenguaje cargado.
- Temas: reutilizar etiquetas existentes (se pasan las 50 más usadas) para que
  las proposiciones se agrupen en el tiempo.

**Decisiones tipadas** (vía `Decider`, todas sobre un solo registro):

| Pregunta | Tipo |
|---|---|
| ¿Es noticia de interés público uruguayo? | sí/no |
| ¿Estas dos notas cubren el mismo hecho? | sí/no |
| ¿La fuente respalda este hecho? | sí/no |
| ¿Este cambio altera el sentido de la nota? | sí/no |
| ¿Qué tan divisiva es esta proposición? | score 0–1 |
| ¿Es clara, neutral en redacción y opinable? | score 0–1 |

Evaluación: set de ~100 casos etiquetados a mano en `archivo/tests/fixtures/`
para medir precisión de cada decisión antes y después de cambiar de modelo.

| URL | Página |

| `/buscar/?q=` | Búsqueda (Postgres full-text en español sobre historias, hechos, entidades) |

| `/reporte/` | Reporte de investigación (existente, adaptado) |
| `/datos/` | Exports abiertos (CSV/JSON semanales) |

**Historias top del día**: score = n_medios × recencia × (1 + divisividad
máx. de sus proposiciones). Top 20 → recrawl y portada.

**SEO / distribución** (lo que funcionó en resistencia.uy)
- Una página por historia, entidad y cambio, con `<title>` y meta propios.
- JSON-LD (`NewsArticle` no, porque no somos el medio: `ClaimReview` no
  aplica tampoco; usar `CreativeWork` + `citation`).
- Sitemaps por tipo (extender `core/sitemaps.py`).
- Imágenes OG generadas server-side (Pillow) para historia, cambio y tarjeta de
  juego. Monocromo, tipografía de la marca.
- PWA: manifest + service worker mínimo (instalable, offline de la jornada).
- Botón "compartir por WhatsApp" en todo.

**Presentación de procedencia**: cada hecho muestra chips de los medios que lo
respaldan; al tocar se ve la cita breve, fecha y link. Si hay snapshot, se
muestra su hash y fecha de captura ("capturado 12/03 14:05 · sha256 …").

## 7. Juego diario

**Armado de la jornada (05:30)**
1. Candidatas: proposiciones `publicada` de historias de las últimas 48 h con
   `calidad ≥ 0.7`.
2. Ranking: n_medios de la historia × divisividad estimada.
3. Diversidad: máximo 1 por historia y 2 por categoría; al menos 1 "probable
   consenso" (divisividad baja) para que no sea todo grieta.
4. Más 1 proposición "recurrente" de un tema de semanas anteriores (ancla para
   el clustering: aumenta el solapamiento entre días).
5. Total 5. Staff puede reemplazar en el admin hasta las 07:00.

**Interacción** (una pantalla por proposición, mobile-first, HTMX)
1. Proposición + link "¿de qué se trata?" (abre resumen y hechos).
2. Botones: De acuerdo / En desacuerdo / No sé.
3. "¿Qué % de Uruguay está de acuerdo?" → 5 botones: 0–20, 20–40, 40–60,
   60–80, 80–100.
4. Resultado inmediato: % actual (marcado "provisorio" si < 30 votos) y si
   acertaste el bucket.

**Puntaje**: 1 punto por bucket acertado, evaluado contra el resultado al cierre
del día (23:59). Durante el día se muestra provisorio. Tarjeta:

```
memoria.uy · 21/11
Leí a Uruguay 4/5
🟩🟩⬜🟩🟩
racha 🔥 6
```

**Sin cuenta**: votos por sesión (patrón existente). Cuenta opcional para
racha entre dispositivos, historial y "mi burbuja". El signup prompt existente
se dispara tras la 3ª jornada completada, no tras el 3er voto.

**Votar desde el archivo**: cualquier proposición publicada se puede votar desde
su historia, en cualquier momento (suma al clustering, no al puntaje).

## 8. Clustering

- `core/clustering/matrix_builder.py`: generalizar
  `build_vote_matrix(model=..., item_field=..., encoding=...)`.
  Encoding: acuerdo = +1, desacuerdo = −1, no sé = ε (igual que neutral hoy).
- Ventana: 60 días (las proposiciones recurrentes aumentan solapamiento).
- Umbral para correr: ≥ 50 votantes con ≥ 5 votos (configurable).
- Proyección de proposiciones en el mapa: reemplaza `NoticiaProjection`.
- Consenso / puentes / evolución: misma lógica; cambiar FK de noticia a
  proposición en `consensus.py`, `bridges.py`, `evolution.py`.
- Nombres de burbujas: `ClusterNameCache` con hash de top proposiciones + entidades.
- En la página de entidad: "cómo ve cada burbuja a X" = promedio de votos en
  proposiciones vinculadas a X, por burbuja.

## 13. Fases

### Fase 1 — Archivo (sin votos)

1. Crear app `archivo`; modelos, migraciones, admin.
2. Seed de medios (lista inicial §14) con RSS/sitemaps y patrones.
3. Providers: Extractor (pago + trafilatura), Storage (R2), Embed, Decider.
4. Tasks: descubrir, filtrar, extraer, agrupar, procesar, verificar, cerrar.
5. Recrawl + Cambio + analizar_cambio.
6. Páginas: home "lo que pasó hoy", historia, entidad, cambios, medio, día, búsqueda.
7. SEO: sitemaps, OG images, PWA.
8. Limpieza §9 (extensión, proxies, submit).
9. Resumen diario de staff con métricas de ingesta y costo.

**Aceptación**: 7 días seguidos corriendo solo; ≥ 90 % de medios activos con
fuentes diarias; ≥ 85 % de hechos marcados fieles en una muestra manual de 50;
costo diario dentro de cupo; al menos un cambio de titular real detectado.

### Fase 2 — Juego diario

1. App `juego`; modelos, armado de jornada, override en admin.
2. UI de jornada (HTMX, mobile-first), voto + predicción, resultado provisorio.
3. Puntaje al cierre, racha, tarjeta compartible + OG image.
4. Votar proposiciones desde la historia.
5. Sesiones + claim de votos extendido a `VotoProposicion`; signup tras 3ª jornada.

**Aceptación**: jornada publicada sola 7 días seguidos; flujo completo en
< 60 s en mobile; tarjeta se ve bien en WhatsApp.

### Fase 3 — Burbujas sobre proposiciones

1. Generalizar `matrix_builder`; modelos de proyección/patrón por proposición.
2. Adaptar consensus, bridges, evolution, nombres de burbujas.
3. Mapa `/burbujas/` y "cómo ve cada burbuja a X" en entidades.
4. Reporte `/reporte/` sobre proposiciones.

**Aceptación**: corre con datos sintéticos en tests; con datos reales cuando
haya ≥ 50 votantes elegibles; silhouette reportado en el reporte.

### Fase 4 — Datos abiertos y cierre de lo viejo

1. Exports semanales `/datos/` (historias, hechos, proposiciones, votos
   agregados por burbuja; nunca votos individuales).
2. API pública de solo lectura (DRF, ya está instalado).
3. Export legacy y borrado de `Noticia`/`Voto` viejos.
4. Actualizar VISION.md, CLAUDE.md, README.
